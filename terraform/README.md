# Terraform infrastructure

SCAPE provisions one isolated Terraform root module per service. The generated root is stored at `environments/<service-id>/`; its remote state is stored under `services/<service-id>/terraform.tfstate` in an encrypted S3 bucket and locked with DynamoDB.

## Layout

```text
terraform/
├── bootstrap/             # Encrypted S3 state bucket and DynamoDB lock table
├── foundation/            # Platform provisioning/cost roles and GitHub OIDC provider
├── modules/
│   ├── iam/                # Account-level IAM foundation
│   ├── nodejs-api/         # VPC, ECS on Fargate or EC2, RDS, ALB, ECR and deploy role
│   └── static-frontend/    # Private S3 origin, CloudFront and deploy role
└── environments/          # Generated service roots (gitignored)
```

## Account setup

Use an AWS deployment identity with permission to create the bootstrap resources. The SCAPE backend runtime must already have an IAM role; pass its exact ARN to the foundation stack.

1. Create the state bucket and lock table. The bootstrap stack starts with local Terraform state and protects both resources from accidental destruction.

   ```sh
   cd terraform/bootstrap
   terraform init
   terraform apply -var='state_bucket_name=your-globally-unique-scape-state-bucket'
   ```

2. Create platform roles and register GitHub Actions OIDC once per AWS account. The backend runtime role must be allowed to call `sts:AssumeRole` and `sts:TagSession` on the provisioning role, and `sts:AssumeRole` on the cost role.

   ```sh
   cd ../foundation
   cp backend.tf.example backend.tf
   terraform init -migrate-state \
     -backend-config='bucket=your-globally-unique-scape-state-bucket' \
     -backend-config='key=foundation/terraform.tfstate' \
     -backend-config='region=ap-south-1' \
     -backend-config='dynamodb_table=scape-tf-locks' \
     -backend-config='encrypt=true'
   terraform apply \
     -var='backend_role_arn=arn:aws:iam::123456789012:role/ScapeBackendRole' \
     -var='state_bucket_name=your-globally-unique-scape-state-bucket'
   ```

3. Set the returned provisioning and cost role ARNs as `AWS_PROVISIONING_ROLE_ARN` and `AWS_COST_EXPLORER_ROLE_ARN`. Set `TF_STATE_BUCKET` and `TF_LOCK_TABLE` to the same names. The backend role needs an identity policy allowing the two STS assume-role calls described above.

The GitHub App installation must have repository administration, contents write, Actions write, and webhook write permissions for the service repositories. The foundation stack creates the account OIDC provider; each service module creates a separate deploy role that trusts only that service repository's `main` branch.

## Module inputs and outputs

Both service modules accept `service_name`, `service_id`, `github_repository`, `region`, `environment`, `owner_team`, and `tags`. The API module also accepts `compute_mode`, `ec2_instance_type`, `requested_vcpu`, and `requested_memory_gib`. EC2 mode creates one ECS container host using the selected instance type; Fargate mode uses the requested task CPU and memory. The generated root exposes the service endpoint, resource ARNs, repository details, deploy role ARN, and template-specific deployment outputs to the worker.

Provisioned resources carry `forge:service-id`, `forge:team-id`, `forge:template-id`, `Environment`, and `ManagedBy=scape` tags. Database passwords are generated by RDS and read by ECS tasks from Secrets Manager; they are not stored in Terraform variables or application code.

The API module creates an ECS service with desired count zero until the first GitHub Actions build pushes an image. In EC2 mode, one EC2 container host is created with the service; in Fargate mode, AWS supplies the task compute. The workflow then enables one task and waits for ECS stability. The current API module endpoint uses HTTP; configure an ACM certificate and HTTPS listener or keep the service behind a trusted TLS-terminating network layer before exposing it to production traffic.

Terraform provider validation and cloud apply require access to Terraform Registry and an AWS account. Apply was not run as part of this repository review.
